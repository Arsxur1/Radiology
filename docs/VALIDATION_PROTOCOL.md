# CardioLens — протокол клинической валидации (проект)

Статус: **исследовательский прототип, не медицинское изделие.** Все числа в
README и CLINICAL_REFERENCES получены на открытых базах (PTB‑XL, ecg‑arrhythmia,
CPSC‑2018, PTB Diagnostic DB, LUDB, PTB‑XL+) против их собственных меток. Эти
метки — ярлыки наборов данных (SCP‑коды, SNOMED, заключения автоматических
алгоритмов, дата инфаркта), а не адъюдицированные клинические исходы, и ни одно
из этих чисел не является заявлением о клинической эффективности. Документ
описывает, что должно быть сделано, чтобы такое заявление стало возможным, и
какие части уже обеспечены кодом.

## 1. Назначение и позиционирование

- **Назначение:** поддержка интерпретации 12‑канальной ЭКГ покоя взрослых и детей
  (ТЗ §1) с режимами A (черновик заключения для врача) и B (автономный вывод
  с обязательной эскалацией критических находок, ТЗ §2, §10).
- **Регуляторная позиция:** программное обеспечение как медицинское изделие,
  поддержка принятия решений. Заключение подписывает врач; режим B допускается
  только для классов, прошедших планку §5 этого протокола. До завершения
  исследования — класс «исследовательское использование».
- **Что заявляется:** чувствительность/специфичность по классам находок и по
  ярусам риска, MAE интервалов, корректность эскалации, калибровка уверенности,
  заземление утверждений LLM (ТЗ §16).

## 2. Дизайн исследования

**Тип:** ретроспективно‑проспективное диагностическое исследование точности
(STARD 2015), два этапа.

**Этап 1 — ретроспективный, размеченный набор.**
ЭКГ из клинических архивов участвующих центров с полным заключением; эталон —
независимое чтение двумя кардиологами, разногласия — третьим (адъюдикация).
Чтение слепое к выводу системы и друг к другу. Для STEMI эталон дополняется
исходом: ангиографически подтверждённая окклюзия или тропониновая динамика с
клиническим диагнозом (не «инфаркт по дате», как в PTBDB).

**Этап 2 — проспективный, последовательные пациенты.**
Все ЭКГ отделений неотложной помощи и кардиологии за период набора; система
работает в тени (вывод не показывается лечащему врачу), эталон — тот же
адъюдицированный протокол плюс исход через 30 дней.

**Критерии включения:** 12‑канальная ЭКГ покоя ≥ 10 с, любой возраст (детские
полосы — отдельная страта с собственным размером выборки). **Исключения:**
технически непригодные записи (SQI ниже порога системы — учитываются отдельно
как «отказ»), пациенты с кардиостимулятором (вне ТЗ §7).

## 3. Конечные точки

Первичные:
1. **Чувствительность критического яруса на уровне случая** (st_elevation,
   complete_av_block, long_qt, peaked_t_waves — `configs/risk_tiers.yaml`):
   доля случаев с хотя бы одной критической находкой в эталоне, по которым
   система выдала хотя бы одну критическую находку (в режиме B — эскалацию).
2. **Доля ложных критических тревог на уровне случая.**

Вторичные: чувствительность/специфичность по каждому классу и по ярусам
major/minor; MAE PR/QRS/QT против разметки волн (контроль — LUDB); доля
корректных эскалаций в режиме B; ECE калибровки; 100 % заземление утверждений
LLM (автопроверка, ТЗ §9); точность оцифровки на реальных снимках (r трассы,
согласие наборов находок с цифровой записью).

## 4. Размер выборки

Для первичной точки при ожидаемой чувствительности 0.92, нижней границе
95 % ДИ ≥ 0.85 и двустороннем α 0.05 требуется ≈ 150 случаев с критической
находкой в эталоне. При распространённости критических находок ≈ 8 % в потоке
неотложной помощи это ≈ 1 900 последовательных ЭКГ на этапе 2; доля ложных
тревог оценивается на оставшихся ≈ 1 750 с полушириной ДИ ≈ 1 %. Детские
страты (< 1 г, 1–3, 3–8, 8–15 лет) — по 100 записей на полосу минимум для
оценки интервалов и оси; детские критические находки редки и заявляться по
чувствительности не будут.

## 5. Критерии приёмки (ТЗ §16)

| Ярус / метрика | Порог | Где считается |
|---|---|---|
| critical, чувствительность на уровне случая | ≥ 0.90 (нижняя граница ДИ ≥ 0.85) | `validate` → `risk.critical.case_sensitivity` |
| critical, ложные тревоги на уровне случая | ≤ 0.05 | `risk.critical.case_false_alert_rate` |
| major, чувствительность / ложные | ≥ 0.80 / ≤ 0.10 | `risk.major` |
| minor | ≥ 0.70 / ≤ 0.20 | `risk.minor` |
| MAE PR / QRS / QT против разметки волн | ≤ 12 / 12 / 20 мс | `--ludb`, `pr_mae_ms` … |
| заземление LLM | 100 % | `layer6_interpret` grounding validator |
| калибровка уверенности | ECE ≤ 0.05 | `calibration/` |
| режим B | критические классы: sens ≥ 0.95 при spec ≥ 0.95; остальное — только с эскалацией | `policy.py`, `risk` |

Планка режима B строже планки режима A намеренно (ТЗ §16): автономный вывод
допускается только для классов, прошедших её на этапе 2.

## 6. Анализ ошибок

Каждая ошибка классифицируется по трём осям: **ярус риска** (critical / major /
minor, `configs/risk_tiers.yaml`), **источник** (приём/оцифровка, предобработка,
измерение, правило, причинный слой, LLM) и **корректируемость** (порог таблицы
норм → калибруется на обучающей половине; логика правила → изменение кода с
записью в DECISIONS; предел данных → документируется). Харнесс печатает по
ярусам пропуски и ложные вызовы по кодам (`validate`, блок «error analysis by
clinical risk tier»); разбор каждого критического пропуска — обязательная часть
отчёта (как сделано для PTBDB и LUDB в CLINICAL_REFERENCES).

## 7. Что уже обеспечено кодом

- Харнесс с метриками по классам, семействам, ярусам риска и возрастным стратам
  (`cardiolens.validation`), JSON‑вывод для статистического отчёта.
- Разделение train/test при калибровке порогов (хеш записи), фиксированные
  конфиги норм — воспроизводимость.
- Безопасный слой §10 независим от LLM и ML; эскалация в режиме B на любую
  критическую находку.
- Трассируемость: каждое утверждение заключения привязано к признаку или
  ребру графа; JSON несёт версии конфигов и режим.

## 8. Чего нет и почему система остаётся прототипом

- Нет адъюдицированного эталона: все метки — ярлыки баз. Чувствительность алерта
  STEMI 0.23 на PTBDB измерена против «инфаркт ≤ 1 дня по дате», а не против
  «STEMI на ЭКГ».
- Нет проспективных данных и исходов; нет детей до 3 лет ни в одном
  достижимом наборе; нет реальных фотографий ЭКГ.
- Нет оценки воспроизводимости между центрами и аппаратами (все открытые базы —
  одна‑две модели электрокардиографов).
- Нет анализа подгрупп по полу и этнической принадлежности (в базах есть пол;
  анализ по полу — следующий шаг харнесса).

## 9. Отчётность

Результаты публикуются по STARD 2015 с блок‑схемой потока записей, таблицами
2×2 по классам и ярусам, ДИ Вилсона, анализом отказов (записи ниже SQI) и
полным перечнем критических пропусков с разбором. Код и конфиги фиксируются
тегом релиза; датасеты не публикуются (лицензии).
