# DECISIONS — журнал инженерных решений (ТЗ §0)

Обоснование ключевых решений. Обновляется по мере развития проекта.

## D1. Язык и стек — Python 3.11+
ТЗ §14. Зрелая экосистема ЭКГ/DSP (`neurokit2`, `wfdb`, `pyedflib`, `scipy`,
`pywavelets`) недоступна в JS. Код — на английском; пользовательские заключения
— RU + UZ (§0).

## D2. Слои как заменяемые модули за контрактами
ТЗ §3, §14. Каждый слой (`layer1..layer6`, `safety`, `outputs`) зависит только
от pydantic-контрактов в `contracts/`, не от реализации соседей. Это позволяет
заменить, например, rule-based Слой 4 на DL-модель (§17 v2) без переписывания
остального.

## D3. Единое представление сигнала в мкВ
ТЗ §3, §4. `SignalRepresentation` — единственный вход для Слоёв 2–6. Все парсеры
конвертируют в микровольты. Сигнал хранится как numpy-массив
`[n_leads, n_samples]`; JSON-экспорт — вложенные списки.

## D4. База каузальных правил — декларативный YAML, не код
ТЗ §8, §18 п.3. Патофизиологические цепочки живут в
`configs/rules/pathophysiology.yaml` и валидируются схемой `RuleBase`. Логика
Слоя 5 (`networkx`) только исполняет правила. Добавление цепочки = правка YAML,
без изменения кода. Стартовые правила: гипер-/гипокалиемия, ГЛЖ-strain,
реверс электродов LA/RA.

## D5. Нормы — конфиг по возрасту/полу, не константы
ТЗ §0, §6. `configs/norms/{adult,pediatric}.yaml`. Педиатрические нормы
возраст-зависимы (ЧСС по возрастным полосам) и включают вариант нормы —
ювенильная инверсия T в V1–V4 (§7.2), чтобы не выдавать её за ишемию.

## D6. Данные примера — синтетика (offline) + хук PTB-XL
ТЗ §12, §15. Ядро офлайн-детерминировано → синтетический 12-канальный генератор
как тестовый стимул (не клиническая модель). Реальный клинический бенчмарк —
PTB-XL — грузится по локальному пути (не бандлим: большой, лицензируется).
Генератор параметризуем (ЧСС, PR, QT, амплитуда T, ST-элевация) для покрытия
детекторов; QT по умолчанию рейт-адаптивный (обратный Bazett), чтобы на высоких
ЧСС не давать ложно-короткий QT.

## D7. QRS/делинеация — neurokit2, не собственный DSP
ТЗ §6, §14. Pan–Tompkins + вейвлет уже реализованы и валидированы в neurokit2.
Где делинеация ненадёжна — помечаем `note` и оставляем `None`, не выдумываем
значение (§0).

## D8. ST-элевация измеряется в точке J, не J+60
Клинически STEMI определяется по элевации в точке J. На высоких ЧСС J+60/J+80
попадают на восходящее колено T-волны и дают ложную «элевацию». J+60/J+80
сохраняются в выходе, но находка `st_elevation` ключится на J-точку. Базовая
линия ST — сегмент PR (за 20 мс до QRS onset) по каждому удару, а не глобальная
медиана.

## D9. LLM-провайдер — абстракция; Claude + offline Stub
ТЗ §9, §12. `LLMProvider` с двумя реализациями: `ClaudeProvider` (облачный
нарратив Anthropic) и `StubProvider` (детерминированный, офлайн — для тестов и
полного офлайна). Слой 6 работает без сети/ключа; Claude подключается, если
доступны `ANTHROPIC_API_KEY` и пакет `anthropic`. Локальная LLM — v2 (§12).

## D10. Заземление — defense in depth
ТЗ §9, §16. Модель инструктируется ссылаться на токены-основания, но
`validate_grounding` независимо отбрасывает любое утверждение без валидной
ссылки (evidence/finding/узел/ребро/активированное правило). Критерий приёмки
§16: 100% выживших утверждений заземлены.

## D11. Safety-слой независим от LLM и режима
ТЗ §10. `scan_critical` работает над находками+измерениями до интерпретации.
Приоритет — recall (чувствительность): паттерн гиперкалиемии, STEMI, длинный QT,
тяжёлая брадикардия, широкие тахикардии. В режиме B критическая находка (или
критическое каузальное правило) форсирует эскалацию. Каждый алерт логируется.

## D12. Трассируемость
ТЗ §1, §11, §12. Финальный JSON содержит версии схемы и базы правил, режим,
критические флаги и построчный audit-log по слоям — основа regulator-readiness.

## D13. Веб-приложение — FastAPI + одностраничный UI
ТЗ §14 (FastAPI) и исходное пожелание «веб-приложение». Пайплайн обёрнут в
HTTP-сервис (`cardiolens.api`) с загрузкой файла/выбором демо-случая и выдачей
всех пяти форматов (§11). Хранилище результатов — in-memory по `analysis_id`
(MVP; для production — БД/объектное хранилище, отдельный воркер). UI —
самодостаточный HTML без внешних зависимостей, тема light/dark.

## D14. Морфологические находки тестируются на уровне измерений
БНПГ (БПНПГ/БЛНПГ), WPW, ФП зависят от тонкой морфологии, которую
синтетический генератор не может чисто провести через делинеацию neurokit2
(широкий QRS/отсутствие P искажают измерения). Поэтому логика этих находок
проверяется детерминированными юнит-тестами на уровне `Measurements`
(`test_findings_rules.py`), а не end-to-end на синтетике; end-to-end валидация —
на реальной PTB-XL. Демо-случаи ограничены надёжно воспроизводимыми паттернами
(ритм/интервалы/ST).

## D15. Валидация — источник-агностичный харнесс
ТЗ §15, §16. `validation.run_validation` принимает размеченные случаи и считает
sens/spec + interval MAE. Два адаптера: синтетический (offline, ground truth
известен — оптимистичная оценка end-to-end делинеации, честно помечена) и
PTB-XL (локальный чекаут; SCP→our-code маппинг; сеть к PhysioNet в рантайме не
нужна — окружение её блокирует). Синтетический PR MAE ~40 мс отражает
систематическое смещение измерения PR (P onset↔QRS onset) — цель калибровки на
реальных данных.

## D15a. Валидация на реальном PTB-XL и калибровка детектора ФП
После открытия egress прогнали харнесс на сбалансированном по SCP-меткам
сабсете PTB-XL (по ~30 записей на класс, 268 всего, `records500`). Скоринг
ведётся по набору меток источника (`PTBXL_SCORED_LABELS`, выводится из
`PTBXL_SCP_TO_CODE`), а не по фиксированным синтетическим 6 — иначе таблица
засоряется классами с нулевой опорой, а морфология (БНПГ/ФП/ГЛЖ) не скорится
вовсе. Прогон вскрыл баг: **ФП давала 0.0 sensitivity** — правило требовало
«отсутствие P-волн» (`p_wave_ratio < 0.3`), но делинеатор neurokit2 ставит «P»
почти на каждом ударе и при ФП, так что `p_wave_ratio ≈ 0.9–1.0` и жёсткий гейт
молча подавлял все детекции. Признак ФП — нерегулярно-нерегулярный ритм, поэтому
основной критерий теперь `rr_cv ≥ _AFIB_RR_CV_MIN` (0.15, подобрано по колену
sens/spec на сабсете: ФП 0.0→0.82 sens при 0.82 spec), а низкий `p_wave_ratio`
лишь повышает уверенность. Подавление синусовой метки при ФП рассматривали и
отвергли: на сабсете оно роняло чувствительность к брадикардии (safety-класс)
0.93→0.57 из-за ложных ФП на респираторной синусовой аритмии — размен не в
пользу клинической безопасности.

**Робастность интервалов.** Прогон вскрыл и второй дефект измерения: по-ударная
делинеация на реальных записях даёт физиологически невозможные значения (PR ~70
мс, отрицательный QT), которые тянут медиану записи. `_median_ms` теперь
отбрасывает по-ударные значения вне физиологичного окна (PR 80–400, QRS 40–200,
QT 200–700 мс) перед медианой — грубые ошибки фидуциалов на отдельных ударах
больше не портят интервал. Это подняло 1AVB (0.08→0.17) и БНПГ (LBBB 0.27→0.43),
не задев синтетические PR/QT MAE.

**Предел 1AVB.** Даже после отбраковки медиана PR на gold-1AVB ≈157 мс при
клиническом пороге >200: dwt-делинеатор neurokit2 систематически ставит P-onset
поздно (~50 мс занижения PR, то же смещение и на синтетике). Занижать порог под
артефакт измерения научно неверно (нормальные PR 150–190 поехали бы в ложные
1AVB), а глобальный сдвиг сломал бы специфичность. Поэтому 1AVB остаётся
ограничена качеством делинеации — настоящее решение — лучший делинеатор P-волны
(v2), а не подгонка порога.

**БНПГ и порог полной блокады.** Классификатор проводимости типировал любой
широкий QRS без положительного терминала в V1 как LBBB — но отрицательный
терминал в V1 это норма (там обычно rS/QS), так что LBBB становился «свалкой» для
любого не-RBBB расширения. Плюс он срабатывал уже при QRS > верхней нормы (110
мс), тогда как полная блокада определяется при **≥120 мс** (110–120 — неспецифичное/
неполное расширение). Ввели порог полной блокады в конфиг норм
(`intervals_ms.qrs_complete_block`: 120 взрослые / 100 дети): QRS в диапазоне
110–120 теперь `wide_qrs_nonspecific`, а не полная БНПГ. Это подняло
специфичность LBBB (0.70→0.76) при почти той же чувствительности.

Остаточный предел БНПГ — снова качество делинеации: QRS-ширина систематически
завышается (медиана QRS на не-БНПГ записях ≈114 мс, у 43% ≥120 мс, хотя в
популяции это редкость — dwt ставит границы QRS слишком широко). Отбраковка
по-ударных выбросов (в т.ч. верхняя граница 200 мс) частично помогает, но
базовое смещение остаётся v2-задачей делинеации, как и с PR.

**ST-находки: корректный gold.** Изначально `AMI`/`IMI` мапились в
`st_elevation`, но это коды класса MI (инфаркт, преимущественно старые Q-рубцы
без острой элевации) — детектор верно НЕ находил на них элевацию, что давало
ложно низкую чувствительность. Исправлено: `st_elevation` теперь из кода `STE_`
(«non-specific ST elevation»), `STD_`→`st_depression`, а коды ИМ не мапятся (у
нас нет находки «старый ИМ»). После этого st_elevation = 0.14 при честном gold:
`STE_` — мягкая неспецифичная элевация (медиана макс. J-точки ≈87 мкВ), а
`st_elevation` намеренно откалиброван на STEMI-уровень (≥100 мкВ = 1 мм) для
safety-алерта (§10). Это рассогласование тяжести, а не дефект — занижать порог
STEMI под неспецифичную элевацию нельзя (убьёт специфичность критического
алерта). st_depression: sens 0.73, spec 0.50 — но ~половина «ложных» несёт
LVH/БНПГ (вторичная реполяризация/strain, не кодированная как `STD_`), т.е.
клинически реальна; специфичность на патологически-обогащённом сабсете занижена.

**Кросс-датасет Chapman/Ningbo (ecg-arrhythmia).** Прогнали адаптер
`build_ecg_arrhythmia_dataset` на сабсете 299 записей (метки SNOMED из `#Dx`
заголовков, 16 скорящихся классов). macro-sensitivity 0.70. Главное:
фикс ФП генерализуется на другой датасет (ФП 0.76), частотные классы сильны
(синусовый/бради/тахи 0.98–1.0), ось/ГЛЖ/низкий вольтаж рабочие (0.75–1.0).
Вскрылась находка того же класса, что и с ФП: **правила трепетания предсердий и
полной АВ-блокады инертны** — они читают `atrial_rate_bpm`/`av_dissociation`,
которые Layer 3 не вычисляет (всегда None). Трепетание: 0/67. В отличие от ФП,
простого надёжного дискриминатора нет: одноканальный FFT-пик в полосе трепетания
(4–6 Гц) даёт ложные срабатывания на ~1/4 не-flutter записей (медиана частоты
предсердий 282 у flutter vs 228 у прочих — распределения перекрываются;
prominence не разделяет). Надёжная детекция требует подавления QRS +
анализа организованности предсердной активности — это v2. Крутой ложно-
срабатывающий детектор клинически вреден (ложное трепетание), поэтому не
внедряем наспех (§0); поля и правила помечены как неизмеряемые/инертные, чтобы
код не подразумевал несуществующую способность.

**LUDB: смещение делинеации измерено.** Добавили режим валидации точности
делинеации (`validation.validate_ludb_delineation`, CLI `--ludb`): сравнение
наших PR/QRS/QT с экспертной разметкой границ LUDB (по-отведенческие аннотации
`(`/peak/`)`, лид II). На сабсете 37 записей гипотеза о смещении фидуциалов
подтвердилась числами:

| интервал | bias (наш − gold, сырой) | MAE (среднее) |
|----------|--------------------------|---------------|
| PR       | **−34 мс**               | 39 мс |
| QRS      | **+8 мс**                | 23 мс |
| QT       | −11 мс                   | 39 мс |

PR систематически занижается на ~34 мс (dwt ставит P-onset поздно) — прямая
причина провала 1AVB (истинный PR >200 читается ~166). QRS завышается (+8 мс
медиана, у отдельных записей до +37) — вклад в ложные БНПГ. Смещение измерено на
той же связке (лид II, dwt), что и в пайплайне, поэтому его можно
использовать как цель калибровочной коррекции (следующий шаг), а не гадать.

**Калибровочная коррекция PR (по измеренному смещению).** Раз смещение измерено
на той же связке (лид II, dwt), его применяем как аддитивную config-коррекцию
(`app.yaml → delineation_correction`, по D5 — в конфиге, не в коде): PR += 34 мс.
Это НЕ изменение клинического порога (>200 мс остаётся) — это устранение
инструментального смещения. Эффект: синтетический PR MAE 41→7, LUDB PR-bias
−34→0, 1AVB на PTB-XL 0.17→0.39. Специфичность 1AVB падает (0.93→0.80) —
честное следствие: раньше «мало ложных» было артефактом тотального занижения, а
теперь PR центрирован и клинический порог ловит пограничные случаи. QRS-коррекцию
не применяем: смещение мельче (+8 мс) и с большим разбросом (MAE 16), глобальный
сдвиг режет истинно-широкие RBBB (sens 0.50→0.37) при малом выигрыше, а
специфичность БНПГ уже закрыта порогом полной блокады. QT не корректируем —
LUDB-смещение (−11) расходится с синтетическим ground truth.

**Расширение сабсетов.** Для устойчивости чисел по редким классам сабсеты
увеличены: PTB-XL до 704 записей (до ~90/класс, стратификация по SCP),
Chapman/Ningbo до 606 (до 50/класс, прескрининг заголовков по `#Dx` SNOMED).
Числа устойчивы: PTB-XL macro 0.63 не изменилась при росте опоры с ~30 до ~90/
класс. Chapman macro на сбалансированном сабсете 0.65 (прежние 0.81 были раздуты
доминированием синусовой брадикардии); трепетание 0/132 — инертность
подтверждена на большой опоре. Полный свод — docs/VALIDATION.md.

**Трепетание: исследование признаков (этап 1, отрицательный).** На
расширенном сабсете (132 flutter / 474 не-flutter) методично проверены 4
признака предсердной активности: (1) FFT-пик в полосе 4–6 Гц — 33% ложных;
(2) спектральная концентрация после вычитания усреднённого QRST — не разделяет
(0.14 vs 0.10); (3) автокорреляция остатка — не разделяет (у flutter даже ниже);
(4) согласие доминантной частоты между отведениями (когерентный источник — на
чистых flutter-записях частота совпадает across II/III/aVF/V1, напр. 322/322/322)
— лучший из проб, но всё равно sens 0.23 при spec 0.91. Общий блокер один:
**остаточная энергия QRS загрязняет предсердный диапазон** (гармоники ЧСС дают
когерентные пики и у не-flutter при простом бланкинге). Вывод этапа: без
качественной отмены QRST (пространственно-временная/PCA-декомпозиция или
выровненное шаблонное вычитание с подавлением остатка) ни один простой признак
не даёт клинически приемлемой специфичности.

**Этап 2 (отмена QRST, отрицательный).** Реализована улучшенная отмена:
по-ударное шаблонное вычитание с тонким выравниванием (кросс-корреляция) и
МНК-масштабированием шаблона. Признак когерентности на очищенном остатке
улучшился лишь незначительно — лучшее sens 0.27 при spec 0.91 (agree≥4,
240–360/мин). Этого мало: при популяционной распространённости трепетания ~1%
и spec 0.91 **PPV ≈ 3%** — почти все флаги были бы ложными. Причина остаточной
загрязнённости — простое шаблонное вычитание не убирает вариабельную морфологию
QRST и Т-волновой остаток.

**Этап 3 (PCA-отмена QRST, отрицательный).** Реализован классический метод
(Langley): выравненные удары → матрица → SVD, верхние K компонент = стереотипный
желудочковый QRST, вычитаем на каждом ударе → предсердный остаток. Прогон на 606
записях (K=2,3,4): prominence спектрального пика на остатке **не разделяет вовсе**
(трепетание 2.8 vs не-flutter 2.8), когерентность частоты между отведениями —
sens 0.16/spec 0.95 (не лучше шаблонного). Причина фундаментальна: записи 10 с
дают лишь 5–15 ударов (PCA чистит плохо), а F-волны трепетания регулярны и утекают
в те же главные компоненты, что считаются «желудочковыми», удаляясь вместе с QRST —
PCA не разделяет два периодических источника без доп. информации. Вывод: рабочая
детекция трепетания требует длинных записей, совместной многоотведенческой
декомпозиции или обучаемой модели — самостоятельный research-проект, не инкремент.
Трепетание остаётся инертным (§0: крутой детектор с плохим PPV не внедряем).

Итог: macro-sensitivity 0.47→0.63 (PTB-XL 704), 0.65 (Chapman/Ningbo 606,
сбалансированный); делинеация измерена на LUDB и PR откалиброван по ней. Числа
синтетические/сабсетные — не клиническая валидация (§0).

## D16. Калибровка уверенности + обратная связь
ТЗ §13, §16. Temperature scaling (единый скаляр T) фитится на
(уверенность, метка) из подтверждений/отклонений врача; ECE — метрика приёмки
режима B. До накопления ≥10 меток — тождество (не выдумываем калибровку, §0).
Правки врача пишутся в append-only JSONL и агрегируются в датасет калибровки.

## D17. Серийное сравнение (§8.4)
Модуль `serial` диффит текущий анализ против предыдущего: новые/разрешившиеся
находки, QTc/ЧСС-дельты. Новая элевация ST или новое удлинение QT — сильный
клинический сигнал: помечаются критично, форсируют эскалацию в режиме B и
повышают уверенность (+0.05). Через API прошлый анализ ищется по `prior_ecg_id`
во in-memory хранилище. Серийная динамика попадает в JSON, заключение RU/UZ и
audit-log.

## D19. Расширение §7: ось, вольтаж, АВ-блокада III, трепетание
- **Отклонение оси** (LAD/RAD/резкое) из измеренной оси QRS + возрастные нормы
  (в педиатрии диапазон шире — правая ось нормальна у новорождённых). End-to-end.
- **Низкий вольтаж QRS**: медиана амплитуды QRS в отведениях I/II/III ниже
  порога. End-to-end (генератор получил `amplitude_scale`).
- **Полная АВ-блокада (III)**: по флагу АВ-диссоциации — критическая (§10),
  форсирует эскалацию. **Трепетание предсердий**: частота предсердий 240–360/мин.
  Оба зависят от измерений, которые синтетика не воспроизводит чисто → тест на
  уровне `Measurements` (паттерн D14); поля `atrial_rate_bpm`/`av_dissociation`
  предназначены для реальных данных.

## D20. Потоковый режим (§4)
`streaming`: `SlidingWindower` буферизует входящие чанки и выдаёт окна
фиксированной длины с перекрытием (10 с / шаг 5 с), абсолютная индексация
держит метки времени стабильными, потреблённые сэмплы отбрасываются
(память ограничена). `StreamProcessor` гоняет каждое окно через полный
пайплайн, сцепляет серийное сравнение окно-к-окну (§8.4) и помечает момент
*появления* критической находки (`new_critical`) — ключевой сигнал для
непрерывного мониторинга. Ядро офлайн (§12); по умолчанию offline-`StubProvider`,
чтобы стриминг не блокировался на сети.

## D21. Оцифровка бумажной ЭКГ (§4)
`layer1_ingestion/digitize.py`: базовый OpenCV-конвейер для **чистого
одноканального** изображения на сетке. Колоночная экстракция трассы (медиана
тёмных пикселей по каждому столбцу, интерполяция разрывов) → сигнал в мкВ по
калибровке (px/mm, mm/s, mm/mV). `provenance.digitized=True`, а
`provenance.confidence` = доля столбцов с найденной трассой, поэтому
деградированное изображение даёт низкую уверенность, а не выдуманный результат
(§0). `render_ecg_image` рендерит сигнал в изображение с сеткой — round-trip
рендер→оцифровка тестируется (корреляция >0.9, ЧСС восстанавливается точно).
Грязные фото, автодетекция калибровки/сетки и мультиотведенческая сегментация —
v2 (§17).

## D22. Hardening API
`api`: in-memory хранилище анализов теперь ограничено (LRU, `STORE_MAX_ENTRIES`)
— долго живущий сервер не растёт без предела; временные файлы под артефакты
(PDF/SVG/PNG) удаляются после отдачи ответа (`BackgroundTask` + очистка
внутреннего temp-каталога в `write_pdf`); загрузка ограничена
`MAX_UPLOAD_BYTES`; имена файлов обрезаются до basename (защита от traversal).
Для production — заменить in-memory store на БД/объектное хранилище.
