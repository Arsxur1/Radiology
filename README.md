# CardioLens — система детекции и интерпретации ЭКГ

Production-grade система интерпретации ЭКГ по [ТЗ](docs/TZ_ECG_CardioLens.md):
6-слойная архитектура с причинно-следственным анализом, LLM-нарративом на
русском и узбекском, двумя режимами работы и полной трассируемостью
(«regulator-ready»).

> **Дисклеймер.** Инструмент поддержки принятия решений. **Не заменяет врача.**
> Не является медицинским изделием; клинически не валидирован.

## Что реализовано (рабочий MVP-срез)

Сквозной конвейер на цифровом входе с **реальными алгоритмами** в каждом слое
(не заглушки), осмысленным подмножеством находок и всеми пятью форматами вывода:

| Слой | Модуль | Содержание |
|------|--------|-----------|
| 1. Приём | `layer1_ingestion` | Парсеры **WFDB, EDF/EDF+, CSV** → единое представление (мкВ, канонические имена отведений); **оцифровка 12-канальной страницы 3×4 + ритм-полоса** с деcкью и устойчивостью к порче фото (`digitize.py`); синтетический генератор (в т.ч. трепетание, АВ-блокада, БНПГ); хук PTB-XL. DICOM/SCP/MUSE/Philips — интерфейсы с `TODO` |
| 2. Предобработка | `layer2_preprocess` | Ресемплинг, режектор 50/60 Гц, полосовой без искажения ST; per-lead SQI, lead-off; **детекция реверса LA/RA** |
| 3. Измерения | `layer3_measure` | QRS (neurokit2 + многоканальная огибающая), P по амплитуде, **конец T касательной по всем отведениям**, PR/QRS/QT, **QTc Fridericia/Bazett/Framingham**, ЧСС/HRV, ось QRS, ST в J/J+60/J+80 от PR-сегмента, вольтаж, **предсердная активность независимо от QRS** (F-волны по спектру, диссоциированные P) |
| 4. Находки | `layer4_findings` | Ритм (синус, бради/тахи, **ФП, трепетание, полная АВ-блокада**), проводимость (**БПНПГ/БЛНПГ, WPW**, АВ-блокада I), интервалы/QT, ишемия (**ST по территориям + реципрокные; перикардит vs STEMI**, нейтральный `st_elevation_any`, вторичные ST-T при БНПГ/ГЛЖ), ГЛЖ, **отклонения оси, низкий вольтаж, увеличение предсердий** — с evidence и confidence; **обучаемый слой** (`ml.py`, sklearn) добавляет `ml_p` как свидетельство и `ml_suggested_*` |
| §10 Safety | `safety` | Критические «нельзя пропустить»: STEMI, длинный QT, паттерн гиперкалиемии, тяжёлая брадикардия, широкие тахикардии — независимо от LLM/режима |
| 5. Каузальный | `layer5_causal` | networkx-граф над YAML-правилами: цепочки причина→следствие, метки физиологично/патологично, флаги неправдоподобности |
| §8.4 Серийное | `serial` | Сравнение с прошлой ЭКГ: новые/разрешившиеся находки, QTc/ЧСС-динамика; новая элевация ST → критично + эскалация |
| 6. Интерпретация | `layer6_interpret` | `LLMProvider`: **Claude**, **локальная OpenAI-совместимая LLM** (Ollama/llama.cpp/vLLM), offline-**Stub**; заземление (drop незаземлённых утверждений); политика режимов A/B/эскалация; RU/UZ |
| §11 Выходы | `outputs` | JSON, заключение RU/UZ, SVG-разметка кривой, каузальный граф, PDF |
| §4 Поток | `streaming` | Скользящие перекрывающиеся окна (10 с, шаг 5 с) с онлайн-обработкой; ловит момент появления критической находки |
| §14 API/UI | `api` | FastAPI-сервис + одностраничный веб-интерфейс: загрузка/выбор → анализ → все 5 форматов |

Конфигурация без хардкода: `configs/app.yaml` (режим, пороги, частота сети),
`configs/norms/{adult,pediatric}.yaml` (возрастные нормы),
`configs/rules/pathophysiology.yaml` (база каузальных правил).

## Запуск демо (сквозной пример, ТЗ §18)

```bash
python -m cardiolens.demo --case normal        # синтетическая норма
python -m cardiolens.demo --case hyperk --mode B   # гиперкалиемия → эскалация
python -m cardiolens.demo --case stemi         # инфаркт → критический алерт
python -m cardiolens.demo --case child         # педиатрические нормы
python -m cardiolens.demo --wfdb <record>      # реальная запись WFDB/PTB-XL
python -m cardiolens.demo --stream             # потоковый режим: STEMI на 20-й сек
```

Все пять форматов вывода пишутся в `outputs/`.

### Реальные данные PTB-XL (ТЗ §15)

PTB-XL не входит в репозиторий (большой, лицензируется на PhysioNet). Скачайте
с <https://physionet.org/content/ptb-xl/> и укажите запись:

```bash
python -m cardiolens.demo --wfdb /path/PTBXL/records500/00000/00001_hr
```

Для офлайн-детерминизма используйте синтетический генератор (по умолчанию).

### LLM-нарратив через Claude (ТЗ §9, §12)

По умолчанию работает offline-`StubProvider`. Для нарратива через Claude:

```bash
export ANTHROPIC_API_KEY=...      # ядро (Слои 1–5) остаётся офлайн
pip install -e ".[llm]"
```

`ClaudeProvider` подключается автоматически, если ключ и пакет доступны;
заземление проверяется в любом случае.

### Полностью офлайн: локальная LLM (ТЗ §12, §17)

Слой 6 умеет работать с любым OpenAI-совместимым сервером — Ollama, llama.cpp,
vLLM, LM Studio. Тот же промпт, те же токены заземления, тот же валидатор.

```bash
ollama serve && ollama pull llama3.1:8b          # http://127.0.0.1:11434/v1
# configs/app.yaml -> llm.provider: "local" (или "auto": Claude → локальный → stub)
python -m cardiolens.demo --case normal
```

Если сервер недоступен или вернул мусор, отчёт всё равно будет — на
детерминированной заглушке, с пометкой в трассе рассуждений. Ключ Claude не
нужен; наружу не уходит ничего.

### Оцифровка бумажной ЭКГ: страница 3×4 (ТЗ §4, §17)

```python
from cardiolens.layer1_ingestion import digitize_page_to_signal, render_ecg_page, degrade_image
sig = digitize_page_to_signal("photo.jpg", px_per_mm=6, mm_per_s=25, mm_per_mv=10)
result = run_pipeline(sig, mode="A")   # sig.provenance.lead_windows — где у отведения есть данные
```

Деcкью по линиям сетки (Hough), порог по отношению к локальной яркости (тень и
сетка не мешают), фильтр связных компонентов (JPEG-звон, соль, подписи
отведений), базовые линии строк из проекции чернил, панели — из геометрии
раскладки. Слой 3 учитывает окна отведений: ось, вольтаж, ST и QT считаются
только по комплексам внутри окна. `render_ecg_page` + `degrade_image` дают
воспроизводимый бенчмарк:

Калибровка теперь читается с изображения (D43): px/mm — из периодичности сетки и
шага строк раскладки, mm/mV — из калибровочного импульса 1 мВ (`render_ecg_page(...,
calibration_pulse=True)`); перспектива фото снимается по точкам схода линий сетки.
Результаты без заданной калибровки (`px_per_mm=None, mm_per_mv=None`), 3 seed:

| Порча | r (6 px/mm) | r (8 px/mm) | ошибка масштаба |
|-------|:--:|:--:|:--:|
| чистый скан, поворот 3°, JPEG 40, тень 50 %, соль 0.5 % | 0.93 | 0.96 | < 1 % |
| размытие 2 px | 0.91 | 0.96 | < 1 % |
| сканерная порча вместе (−2°, размытие, JPEG, тень, соль) | 0.92 | 0.96 | < 1 % |
| **фото**: перспектива 2 %, виньетка, текстура, размытие, JPEG 45, 1.5° | 0.76 | 0.94 | 2–3 % |
| перспектива ≥ 3.5 % (сильное фото) | 0.2–0.3 | 0.1–0.3 | — |

ЧСС, ось и находка STEMI на «фотографии» совпадают с исходным сигналом
(`tests/test_digitize_page.py`). Предел метода по точкам схода — около 2 %
смещения углов; реальные фотографии по-прежнему не проверялись (ECG-Image-Database
недоступна из среды) — честное ограничение.

**Страницы из реальных сигналов PTB-XL (100 записей, автокалибровка):** запись
→ страница → порча → оцифровка → тот же пайплайн; сравнение с цифровой записью:

| Страница | r | ЧСС ≤ 3 уд/мин | ось ≤ 15° | QRS MAE | Jaccard кодов находок |
|---|:-:|:-:|:-:|:-:|:-:|
| чистая | 0.90 | 80 % | 87 % | 25 мс | 0.57 |
| скан (1°, размытие, JPEG 60) | 0.89 | 81 % | 84 % | 24 мс | 0.48 |
| фото 2 % | 0.61 | 39 % | 46 % | 40 мс | 0.33 |
| фото 3.5 % | 0.24 (11 отказов) | 37 % | 16 % | 45 мс | 0.31 |

Ритм и частота со страницы надёжны, набор находок — нет: совпадает полностью
лишь у 18 % чистых страниц. Причина найдена и названа, не спрятана: оцифрованный
QRS систематически шире на +24 мс (медиана) — штрих 2 px при 150 px/с и медиана
столбца делают из 80–90 мс 100–130, и нормальные записи уходят за порог БНПГ
(`lbbb` у 6 из 15 проверенных). Это следующий пункт для оцифровки (утоньшение
штриха до медианы столбца, поправка ширины по толщине штриха) — подробности в
CLINICAL_REFERENCES.

### Обучаемый слой поверх правил (ТЗ §17)

`cardiolens.ml`: признаки v2 — 79 сводных признаков Слоя 3 + 300 признаков формы
среднего комплекса по отведениям (D46) → per-class HistGradientBoosting (sklearn);
набор признаков версионируется, артефакт другой версии отвергается.
Модель — **свидетельство, не авторитет** (D33): вероятность попадает в evidence
находки (`ml_p`), согласие поднимает уверенность, несогласие только фиксируется,
`ml_suggested_<код>` — лишь для классов, где модель точна (spec ≥ 0.95) на всех
наборах и не хуже правил на каждом чужом наборе в обе стороны переноса (≥ 20
позитивов); сейчас таких классов **нет**. Safety-слой ML не видит.

```bash
python -m cardiolens.ml.train --train data/ecg-arrhythmia-train data/ecg-arrhythmia data/ptbxl \
    --holdout data/ecg-arrhythmia-balanced --cross data/ecg-arrhythmia-pediatric \
    --transfer ecgarr=data/ecg-arrhythmia-train ptbxl=data/ptbxl \
    --report configs/models/rhythm_hgb.report.json     # артефакт 18 МБ не коммитится
# configs/app.yaml -> ml.enabled / ml.model_path; без артефакта — только правила
```

Результаты (правила / модель / правила ∪ модель) — таблица в разделе «Валидация» ниже.

## Веб-приложение (FastAPI + UI)

Движок обёрнут в HTTP-сервис с одностраничным интерфейсом: выбор демо-случая
или загрузка файла (WFDB/EDF/CSV) → анализ → заключение RU/UZ, находки,
кривая, каузальный граф, скачивание PDF.

```bash
pip install -e ".[dev]"
uvicorn cardiolens.api.app:app --reload      # → http://127.0.0.1:8000
```

Эндпоинты:

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/` | Веб-интерфейс |
| GET | `/health` | Проверка живости |
| GET | `/api/cases` | Список демо-случаев |
| POST | `/api/analyze` | Анализ: форма с `case` (синтетика) или `files` (загрузка) + `mode`, контекст пациента → JSON (§11) |
| GET | `/api/analysis/{id}/report.pdf` | PDF-заключение |
| GET | `/api/analysis/{id}/waveform.svg` | Размеченная кривая |
| GET | `/api/analysis/{id}/graph.png` | Каузальный граф |
| GET | `/api/analysis/{id}/conclusion?lang=ru\|uz` | Текст заключения |

Пример через curl:

```bash
curl -s -F case=hyperk -F mode=B http://127.0.0.1:8000/api/analyze | jq .mode
# CSV: обязательно указать частоту дискретизации
curl -s -F files=@data/samples/sample_ecg.csv -F sampling_rate_hz=500 -F unit=uv \
     http://127.0.0.1:8000/api/analyze | jq '.measurements.heart_rate_bpm'
```

> Ядро (Слои 1–5) работает офлайн; в облако уходит только опциональный
> LLM-нарратив Слоя 6 (TZ §12). In-memory хранилище анализов — для MVP; в
> production заменить на БД/объектное хранилище.

## Валидация и метрики (§16)

Харнесс валидации не зависит от источника данных: принимает размеченные случаи
(сигнал + gold-находки + gold-интервалы), прогоняет весь пайплайн и считает
per-class sensitivity/specificity и MAE интервалов.

```bash
python -m cardiolens.validate                 # offline синтетический датасет
python -m cardiolens.validate --ptbxl <root>  # реальная PTB-XL (локальный чекаут)
python -m cardiolens.validate --ecg-arrhythmia <root>  # Chapman/Ningbo (локальный чекаут)
```

Синтетический прогон даёт оптимистичные (помеченные как синтетика) числа.

`WFDBRecords/01/010–012`).** Настоящие sens/spec — не синтетика. Первый прогон
вскрыл слабые места; второй столбец — после доработки слоёв 3–4 по его итогам:

| брадикардия | 0.94 / 0.98 | 0.96 / 0.97 | 155 |
| тахикардия | 1.00 / 0.91 | 0.97 / **0.96** | 30 |
| ФП | 0.62 / 0.94 | 0.62 / 0.95 | 61 |
| трепетание | 0.00 / 1.00 | **0.20** / 1.00 | 15 |

Macro-sensitivity 0.65 → **0.72**. Что именно было исправлено и что осталось —
в [CLINICAL_REFERENCES](docs/CLINICAL_REFERENCES.md) (раздел «Measured results»).
Кратко: ширина QRS теперь по многоканальной огибающей (dwt читал БНПГ как узкий
QRS), начало P уточняется по амплитуде (PR на синтетике: MAE 41 → 1 мс), появилось
измерение предсердной активности независимо от QRS (`atrial_rate_bpm`,
`av_dissociation` → трепетание с переменным проведением и полная АВ-блокада), ST
судится по J-точке с плато и контигуальностью, дискордантные изменения при
БНПГ/ГЛЖ помечаются вторичными. Честные ограничения на этом срезе: ФП с почти регулярным желудочковым ответом
не детектируется; БЛНПГ в этом датасете делит SNOMED-код с гемиблоками (шум
меток). Трепетание с фиксированным проведением позже получило спектральный детектор
F-волн (см. PTB-XL ниже).

Сбалансированная выборка: `python -m cardiolens.validation.fetch_physionet --out
data/ecg-arrhythmia-balanced --folders 60 --per-class 80` скачивает заголовки для
разброса папок, отбирает подмножество с капом по классу (редкие классы — первыми)
и докачивает только нужные сигналы; затем `python -m cardiolens.validate
--ecg-arrhythmia data/ecg-arrhythmia-balanced --limit 2000`.

Macro-sensitivity **0.60 → 0.65**. Длинный QT вырос втрое за счёт разметки конца T
по всем отведениям (было 196–290 мс у gold-записей — ошибка dwt, не порога).
Семья ФП ∪ трепетание — 0.49 → 0.77 при spec 0.95: метки «трепетание» в Нинбо (187
записей) в основном имеют нерегулярный ответ без организованных P и правилом
неотличимы от ФП, поэтому семейная метрика честнее поклассовой; спектральный
детектор F-волн на этих метках не срабатывает (на PTB-XL — срабатывает, см. ниже).
Алерт элевации ST намеренно строже метки датасета «ST tilt up» (spec 0.98), охват
метки показывает нейтральный дескриптор `st_elevation_any` (0.83). Ни одной
gold-записи полной АВ-блокады в 4000 заголовках нет — её чувствительность измерена
на PTB-XL.

**PTB Diagnostic DB (549 записей): чувствительность алерта STEMI.** Единственный
достижимый набор с ЭКГ, снятыми в первые дни острого инфаркта (дата инфаркта и
дата ЭКГ в заголовке). Gold — инфаркт с ЭКГ ≤ 3 дней (прокси STEMI):

| Дни от инфаркта | n | алерт `st_elevation` | территория совпала |
|---|--:|:-:|:-:|
| 0–1 | 61 | **0.23** | 13 / 14 |
| 2–3 | 35 | 0.23 | 8 / 8 |

набора (~45k) — перед клиническими выводами прогнать на большей выборке.

## Обратная связь и калибровка (§13)

- **Захват правок врача:** `POST /api/analysis/{id}/feedback` — по каждой
  находке `confirmed | corrected | rejected` пишется в append-only JSONL
  (`cardiolens.feedback`). Топливо для дообучения и калибровки.
- **Калибровка уверенности:** temperature scaling (`cardiolens.calibration`);
  `POST /api/calibration/fit` обучает T на накопленных подтверждениях/отклонениях
  и считает ECE (до/после). До накопления меток — тождество (T=1, no-op).
  Пайплайн применяет калиброванную уверенность к находкам.
