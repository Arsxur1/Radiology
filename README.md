# CardioLens — система детекции и интерпретации ЭКГ

Production-grade система интерпретации ЭКГ по [ТЗ](docs/TZ_ECG_CardioLens.md):
6-слойная архитектура с причинно-следственным анализом, LLM-нарративом на
русском и узбекском, двумя режимами работы и полной трассируемостью
(«regulator-ready»).

> **Дисклеймер.** Инструмент поддержки принятия решений. **Не заменяет врача.**
> Не является медицинским изделием; клинически не валидирован.

## Что реализовано (рабочий MVP-срез)

Сквозной конвейер на цифровом входе с **реальными алгоритмами** в каждом слое
(не заглушки), осмысленным подмножеством находок и всеми пятью форматами вывода:

| Слой | Модуль | Содержание |
|------|--------|-----------|
| 1. Приём | `layer1_ingestion` | Парсеры **WFDB, EDF/EDF+, DICOM-ECG (`.dcm`, `pip install -e ".[dicom]"`), CSV** → единое представление (мкВ); **оцифровка страницы ЭКГ** (OpenCV, `digitize.py`); синтетический генератор; хук PTB-XL. SCP/MUSE/Philips/HL7 — интерфейсы с `TODO` |
| 2. Предобработка | `layer2_preprocess` | Ресемплинг, режектор 50/60 Гц, полосовой без искажения ST; per-lead SQI, lead-off; **детекция реверса LA/RA** |
| 3. Измерения | `layer3_measure` | QRS/делинеация (neurokit2), PR/QRS/QT, **QTc Bazett/Fridericia/Framingham**, ЧСС/HRV, ось QRS, ST в J+60/80, вольтаж Соколов-Лайон |
| 4. Находки | `layer4_findings` | Ритм (синус, бради/тахи, **ФП, трепетание, полная АВ-блокада**), проводимость (**БПНПГ/БЛНПГ, WPW**, АВ-блокада I), интервалы/QT, ишемия (**ST по территориям + реципрокные; перикардит vs STEMI**, T с педиатрической оговоркой), ГЛЖ, **отклонения оси, низкий вольтаж, увеличение предсердий (P-mitrale/P-pulmonale)**, паттерн Бругада; у детей — СВТ, синусовая аритмия вместо ложной ФП, у младенцев — эпизоды брадикардии — с evidence и confidence |
| §10 Safety | `safety` | Критические «нельзя пропустить»: STEMI, длинный QT, паттерн гиперкалиемии, тяжёлая брадикардия (< 40/мин; до 1 года < 60, PALS), широкие тахикардии — независимо от LLM/режима |
| 5. Каузальный | `layer5_causal` | networkx-граф над YAML-правилами: цепочки причина→следствие, метки физиологично/патологично, флаги неправдоподобности |
| §8.4 Серийное | `serial` | Сравнение с прошлой ЭКГ: новые/разрешившиеся находки, QTc/ЧСС-динамика; новая элевация ST → критично + эскалация |
| 6. Интерпретация | `layer6_interpret` | `LLMProvider`: **Claude** + offline-**Stub**; заземление (drop незаземлённых утверждений); политика режимов A/B/эскалация; RU/UZ |
| §11 Выходы | `outputs` | JSON, заключение RU/UZ, SVG-разметка кривой, каузальный граф, PDF |
| §4 Поток | `streaming` | Скользящие перекрывающиеся окна (10 с, шаг 5 с) с онлайн-обработкой; ловит момент появления критической находки |
| §14 API/UI | `api` | FastAPI-сервис + одностраничный веб-интерфейс: загрузка/выбор → анализ → все 5 форматов |

Конфигурация без хардкода: `configs/app.yaml` (режим, пороги, частота сети),
`configs/norms/{adult,pediatric}.yaml` (возрастные нормы),
`configs/rules/pathophysiology.yaml` (база каузальных правил).

## Установка

```bash
python3.11 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"        # ядро + pytest
pip install -e ".[dev,llm]"    # + Claude-провайдер (anthropic)
```

## Запуск демо (сквозной пример, ТЗ §18)

```bash
python -m cardiolens.demo --case normal        # синтетическая норма
python -m cardiolens.demo --case hyperk --mode B   # гиперкалиемия → эскалация
python -m cardiolens.demo --case stemi         # инфаркт → критический алерт
python -m cardiolens.demo --case child         # педиатрические нормы
python -m cardiolens.demo --wfdb <record>      # реальная запись WFDB/PTB-XL
python -m cardiolens.demo --stream             # потоковый режим: STEMI на 20-й сек
```

Все пять форматов вывода пишутся в `outputs/`.

### Реальные данные PTB-XL (ТЗ §15)

PTB-XL не входит в репозиторий (большой, лицензируется на PhysioNet). Скачайте
с <https://physionet.org/content/ptb-xl/> и укажите запись:

```bash
python -m cardiolens.demo --wfdb /path/PTBXL/records500/00000/00001_hr
```

Для офлайн-детерминизма используйте синтетический генератор (по умолчанию).

### LLM-нарратив через Claude (ТЗ §9, §12)

По умолчанию работает offline-`StubProvider`. Для нарратива через Claude:

```bash
export ANTHROPIC_API_KEY=...      # ядро (Слои 1–5) остаётся офлайн
pip install -e ".[llm]"
```

`ClaudeProvider` подключается автоматически, если ключ и пакет доступны;
заземление проверяется в любом случае.
- Модель по умолчанию — `claude-opus-5-5`, переопределяется через `ANTHROPIC_MODEL`.
- В облако уходят только находки, причинные связи и четыре измерения. Пациент и клинический контекст не уходят.
  Каждая строка очищается от похожего на идентификатор текста (`layer6_interpret/phi.py`, D91).
- При отказе модели или ошибке сети используется локальный нарратив, а в трассе остаётся запись об этом.

## Веб-приложение (FastAPI + UI)

Движок обёрнут в HTTP-сервис с одностраничным интерфейсом: выбор демо-случая
или загрузка файла (WFDB/EDF/DICOM/CSV) → анализ → заключение RU/UZ, находки,
кривая, каузальный граф, скачивание PDF.

```bash
pip install -e ".[dev]"
uvicorn cardiolens.api.app:app --reload      # → http://127.0.0.1:8000
```

Эндпоинты:

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/` | Веб-интерфейс |
| GET | `/health` | Проверка живости |
| GET | `/api/cases` | Список демо-случаев |
| POST | `/api/analyze` | Анализ: форма с `case` (синтетика) или `files` (загрузка) + `mode`, контекст пациента → JSON (§11) |
| GET | `/api/analysis/{id}/report.pdf` | PDF-заключение |
| GET | `/api/analysis/{id}/waveform.svg` | Размеченная кривая |
| GET | `/api/analysis/{id}/graph.png` | Каузальный граф |
| GET | `/api/analysis/{id}/conclusion?lang=ru\|uz` | Текст заключения |

Пример через curl:

```bash
curl -s -F case=hyperk -F mode=B http://127.0.0.1:8000/api/analyze | jq .mode
# CSV: обязательно указать частоту дискретизации
curl -s -F files=@data/samples/sample_ecg.csv -F sampling_rate_hz=500 -F unit=uv \
     http://127.0.0.1:8000/api/analyze | jq '.measurements.heart_rate_bpm'
```

> Ядро (Слои 1–5) работает офлайн; в облако уходит только опциональный
> LLM-нарратив Слоя 6 (TZ §12). In-memory хранилище анализов — для MVP; в
> production заменить на БД/объектное хранилище.

## Валидация и метрики (§16)

Харнесс валидации не зависит от источника данных: принимает размеченные случаи
(сигнал + gold-находки + gold-интервалы), прогоняет весь пайплайн и считает
per-class sensitivity/specificity и MAE интервалов.

```bash
python -m cardiolens.validate                 # offline синтетический датасет
python -m cardiolens.validate --ptbxl <root>  # реальная PTB-XL (локальный чекаут)
python -m cardiolens.validate --ecg-arrhythmia <root>  # Chapman/Ningbo (локальный чекаут)
python -m cardiolens.validate --ludb <root>   # точность делинеации: bias+MAE PR/QRS/QT vs экспертная разметка
```

Сводные результаты по всем датасетам (PTB-XL, Chapman/Ningbo, LUDB, MIT-BIH),
методология и ограничения — в [docs/VALIDATION.md](docs/VALIDATION.md).

**Классификатор ударов (желудочковая эктопия).** Находки `ventricular_ectopy` /
`ventricular_bigeminy` даёт прозрачный LDA-классификатор ударов
(`configs/beat_lda.json`; ЖЭ ~0.82 sens / 0.97 PPV на межпациентном MIT-BIH).
Переобучение по локальному чекауту MIT-BIH:

```bash
python -m cardiolens.train_beats --mitdb <root>   # → configs/beat_lda.json
```

Синтетический прогон даёт реальные (оптимистичные, помечены как синтетика)
числа: macro-sensitivity, sens/spec по классам, PR/QT MAE.

Набор скорящихся меток свой у каждого источника — ровно те коды находок,
которые способна выдать его разметка (иначе таблица засоряется классами с
нулевой опорой). Для PTB-XL это `PTBXL_SCORED_LABELS` (ритм, АВ-блокада I,
**БПНПГ/БЛНПГ, ФП, ГЛЖ, ST-элевация**), для Chapman/Ningbo —
`ECG_ARRHYTHMIA_SCORED_LABELS` (+ ось, низкий вольтаж, длинный QT и др.);
списки выводятся из карт меток (`PTBXL_SCP_TO_CODE`, `SNOMED_TO_CODE`), так что
скоринг не расходится с тем, что адаптер реально проставляет как gold. Явный
набор задаётся `--labels code1,code2,...`. Морфологические находки
(БНПГ/WPW/ФП) дополнительно проверяются детерминированными юнит-тестами на
уровне измерений. Сеть к PhysioNet в рантайме не нужна — адаптер читает
локальный чекаут.

## Обратная связь и калибровка (§13)

- **Захват правок врача:** в веб-интерфейсе у каждой находки кнопки «верно» и «неверно», поля «врач»,
  «пропущенная находка» и комментарий. Форма отправляет `POST /api/analysis/{id}/feedback`.
  По каждой находке пишется `confirmed | corrected | rejected | missed` в append-only JSONL (`cardiolens.feedback`,
  путь — `CARDIOLENS_FEEDBACK_PATH`). Уверенность в записи сервер берёт из сохранённого анализа, а не от клиента.
- **Сводка:** `GET /api/feedback/summary` — по каждой находке число вердиктов, доля подтверждённых и средняя
  показанная уверенность. Это локальный аналог PPV, по которой выставлены потолки уверенности (D85–D86).
- **Калибровка уверенности:** temperature scaling (`cardiolens.calibration`). `POST /api/calibration/fit` обучает T
  на подтверждениях и отклонениях и считает ECE до и после. С `?save=true` подогнанный T сохраняется туда, откуда его
  читает пайплайн (`CARDIOLENS_CALIBRATOR_PATH`, по умолчанию `configs/calibrator.json`), если он уменьшил ECE.
  До накопления 10 меток — тождество (T=1).
- **Порядок в пайплайне** (D87): потолок → `confidence_base` → калибратор → снова потолок. Калибратор обучается
  на `confidence_base` и применяется к нему же. Потолки D85/D86 остаются верхней границей: правки врача могут понизить
  уверенность находки, но не поднять её выше потолка (это пересмотр потолка — отдельное решение).

## Архитектура

```
вход → [1] приём → [2] предобработка/качество → [3] измерения
     → [4] находки → [§10 safety] → [5] каузальный анализ
     → [6] интерпретация (LLM, режим A/B) → выходы (JSON/RU-UZ/SVG/граф/PDF)
```

Слои — заменяемые модули за pydantic-контрактами (`src/cardiolens/contracts/`).
Инженерные решения — в [DECISIONS.md](DECISIONS.md).
